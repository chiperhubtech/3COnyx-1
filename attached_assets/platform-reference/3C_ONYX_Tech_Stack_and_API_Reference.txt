1. PLATFORM AT A GLANCE
==========================================================================

3C ONYX is a TypeScript-based automotive platform with a React web application, an Expo/React Native mobile app, an Express API service, and shared PostgreSQL data. This reference covers the implementation found in this workspace, not a certification of production readiness.


COPY-AND-PASTE STACK SUMMARY

Frontend: React 19.1.0, Vite ^7.3.0, TypeScript ~5.9.2, Tailwind CSS ^4.1.14, Radix UI, Wouter ^3.3.5, TanStack React Query ^5.90.21, React Hook Form ^7.55.0, Framer Motion ^12.23.24, Recharts ^2.15.2, Leaflet ^1.9.4 and i18next ^25.10.5.

Mobile: Expo ~54.0.27, React Native 0.81.5, Expo Router ~6.0.17, React Native Web ^0.21.0, Expo SecureStore, device location, camera and notification capabilities.

Backend: Node.js (Replit configuration: Node 24), Express ^5, tRPC ^11.14.1, Zod 3.25.76, ws ^8.20.0, Pino, Helmet, express-rate-limit and request tracing.

Data: PostgreSQL 16 configuration, pg ^8.20.0, Drizzle ORM ^0.45.1, drizzle-kit ^0.31.9, checked-in SQL migrations, optional Redis through ioredis ^5.11.1 and in-memory fallback.

Authentication: bcrypt password hashing, jose JWTs, token revocation and role middleware; Google/Apple token verification and WebAuthn/passkey code. Web tokens use localStorage; mobile tokens use SecureStore. Protection varies by endpoint.

AI and integrations: OpenAI, Google Gemini, Anthropic and Amazon Bedrock client code; Stripe, Shopify, MarketCheck, NHTSA, maps, messaging and other integration implementations. See Section 3 for implementation versus scaffold distinctions.

Tooling: pnpm workspace, TypeScript project references, Orval OpenAPI code generation, esbuild API bundling, Vite web builds, Vitest, GitHub Actions and AWS CDK infrastructure templates.

BASE PATHS AND CALLING CONVENTIONS

REST: use the platform origin followed by /api and the exact path shown in Section 5. Paths in this PDF already include /api; do not add it twice. No published hostname is assumed here. Browser applications should retain the artifact base-path prefix when constructing URLs.

Dynamic parameters use Express notation such as :id or :requestId. Replace them with the actual resource identifier. Methods are significant: GET, POST, PUT, PATCH and DELETE are separate operations.

Protected routes commonly accept Authorization: Bearer <token> or the existing token cookie. Roles and middleware vary by handler; the endpoint inventory deliberately does not label uninspected routes “public” or “secure.” Webhook routes may use provider signatures instead of user authentication.

Example read-only request (placeholders, not credentials):

curl "https://<platform-host>/api/services/requests" \
  -H "Authorization: Bearer <your-session-token>"

Do not automatically run every listed endpoint: the inventory includes destructive operations, payment operations, admin actions, seed/demo endpoints and third-party dispatch requests.
